# SapaRate — оценка качества диалогов

> *Сапа* (каз.) — качество. SapaRate оценивает каждый диалог оператора по чек-листу и показывает доказательства.

Прототип оценки работы операторов в чатах и звонках (RU / KZ / EN) по настраиваемому чек-листу.
Модель отвечает по каждому критерию и указывает реплики-доказательства, **баллы и итог считает код**,
есть апелляция с решением проверяющего и пересчётом, чек-лист редактируется в интерфейсе с версиями.

## Запуск

Нужен **Python 3.10+**.

```bash
pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
python run.py               # открыть http://127.0.0.1:8000
```

На Windows можно просто запустить **`start-lan.bat`**: он установит зависимости и откроет доступ для команды в локальной сети (адрес для коллег появится в окне).

В `.env` заполните:

| Переменная | Что это |
|---|---|
| `DATA_API_URL` | GET-ссылка организаторов (параметр `group_id` подставляется автоматически) |
| `GEMINI_API_KEY` | бесплатный ключ Google AI Studio (aistudio.google.com/apikey) |
| `GEMINI_MODEL` | модель Gemini Flash из списка, доступного вашему ключу в AI Studio |
| `GEMINI_THINKING` | сколько модель «думает»: `minimal` / `low` / `medium` / `high`. `low` — быстро и достаточно точно |
| `OPENAI_API_KEY` | запасной провайдер — любой OpenAI-совместимый API, по умолчанию Groq (бесплатно) |

Без ключей приложение работает в **MOCK-режиме** (оценки-заглушки) — удобно для проверки интерфейса.
Если у основного провайдера закончился бесплатный лимит, оценка автоматически уходит в следующий (`gemini → openai`).

Загрузка данных: страница «Диалоги» → ввести `DEV` → «Загрузить из API». Копия сохраняется в `data/`,
поэтому дальше работает офлайн. Если API недоступен, ответ GET можно сохранить в файл и загрузить кнопкой «Загрузить JSON-файл».

## Контрольный набор (час 23)

```bash
python scripts/batch_eval.py <group_id>          # скачать набор и оценить все диалоги
python scripts/batch_eval.py <group_id> --missing   # дооценить только неоценённые
```

Результаты появляются в интерфейсе и в `reports/<group_id>.csv`. То же самое можно сделать в интерфейсе:
«Загрузить из API» → «Оценить неоценённые».

## Что где

| Требование | Где |
|---|---|
| Настройка чек-листа: критерии, формулировки, вес, тип ответа, N/A, шкала | «Чек-лист». Каждое сохранение — новая версия |
| Оценка диалога выбранным чек-листом, RU/KZ/EN, бот и система — контекст | Карточка диалога → выбрать чек-лист → «Оценить» |
| Ответ, баллы, вес, объяснение, реплика-доказательство | Карточки критериев по секциям |
| Пропущенное действие → проверенный участок | Кнопка «Проверен участок #X–#Y» |
| N/A с причиной, перераспределение веса | Блок «Почему N/A», «вес → … после перераспределения» |
| Грубые ошибки отдельно | Красная плашка в итогах и значок в списке |
| Переход к реплике / моменту записи звонка | Клик по доказательству, по `[N]` в тексте или ▶ у реплики |
| Апелляция по критерию | «Оспорить» → комментарий |
| Решение проверяющего, пересчёт, исходная оценка + решение + итог | «Апелляции» → подтвердить / изменить + причина |
| Замена критерия и повторное применение | «Чек-лист» → правка → «Сохранить как vN» → «Переоценить» |

## Как устроено

```
frontend/  (HTML + CSS + JS, Web Components, без сборки)
   │  fetch /api/...
backend/   (FastAPI)
   ├─ datasource.py  загрузка наборов, время реплик, позиции в аудио, ссылка на запись
   ├─ facts.py       факты, которые считает код: первая реплика оператора, ожидания дольше порога
   ├─ llm.py         промпт из ТЕКУЩЕЙ версии чек-листа → модель → JSON → проверка → 1 повтор
   ├─ scoring.py     ВСЕ формулы итога (вес, N/A, шкалы, округление, грубые ошибки)
   ├─ checklist.py   проверка чек-листа перед сохранением
   ├─ service.py     оценки, пакеты, апелляции
   └─ storage.py     SQLite: storage/cqa.db
```

- **Модель только отвечает** (да / нет / N/A / ступень шкалы), пишет объяснение и номера реплик. Код проверяет,
  что номера существуют, ступень есть в шкале, N/A разрешён; при ошибке модель получает список ошибок и отвечает заново.
- **Доказательства показываются из транскрипта**, а не из текста модели — цитата всегда настоящая.
- **Чек-лист не зашит в код**: промпт собирается из выбранной версии. Новый критерий работает без правки кода.
- **Апелляция не перезаписывает оценку модели**: решение хранится отдельно, итог пересчитывается тем же `scoring.py`.
  В карточке видно: исходный ответ → решение проверяющего с причиной → новый итог.
- **Звонки**: `audio_url` отдаёт страницу плеера со ссылкой на mp3, которая действует около часа. Сервер достаёт
  свежую ссылку при открытии звонка. Паузы записи («запись приостановлена/возобновлена») вычитаются из позиции в аудио
  (`AUDIO_SKIP_PAUSES=0`, если перемотка окажется сдвинута).
- **Dynamics 365**: каждый экран — отдельный компонент (`<cqa-dialog-list>`, `<cqa-evaluation-view>`,
  `<cqa-appeals-view>`, `<cqa-checklist-editor>`). Для встраивания подключить скрипт и задать `window.CQA_API_BASE`
  с адресом бэкенда (CORS открыт).

## Формула итога

См. начало `backend/scoring.py`:

1. Применимые критерии — с весом > 0, не грубая ошибка, ответ не N/A. `W` = сумма их весов.
2. Эффективный вес = вес / W × 100 (вес N/A перераспределяется пропорционально).
3. Да = 100% веса, Нет = 0; шкала = ступень / максимальная ступень.
4. Итог = сумма баллов, округление по чек-листу (по умолчанию 2 знака, half-up).
5. Грубая ошибка помечается отдельно; если в чек-листе включено «Грубая ошибка обнуляет итог» — итог = 0.

Пример из чек-листа: N/A у c03 и c07, c04 = 15, c06 = 7 → 65,5 / 75 × 100 = **87,33** (есть в тестах).

## Модель и стоимость

- Основная: **Gemini Flash** через бесплатный уровень Google AI Studio — **$0** за оценку.
  Запасная: `openai/gpt-oss-120b` через бесплатный уровень Groq.
- Одна оценка = 1 запрос (2, если первый ответ не прошёл проверку). Фактические токены каждой оценки
  записываются и видны в карточке; средние — на странице «Диалоги» и в выводе `batch_eval.py`.
- Чтобы показать стоимость на платном тарифе, задайте `PRICE_INPUT_PER_1M` / `PRICE_OUTPUT_PER_1M` (USD за 1 млн токенов)
  по прайсу выбранной модели: стоимость = вход × цена входа + выход × цена выхода.

## Сложный тестовый кейс

`hard_case_HARD.json` — диалог с ловушкой на каждый критерий: ответ оператора не на языке клиента, переспрос уже известных данных, шаблонная эмпатия, предупреждённое и непредупреждённое ожидание, предложение кода из SMS (оператор правильно отказывается), клиент уходит до прощания. Загрузите его кнопкой «Загрузить JSON-файл». Эталон: c01 Нет, c02 Нет, c03 Да, c04 15, c05 Нет, c06 7, c07 N/A, c08 Нет → итог **47,89**.

## Тесты

```bash
python -m pytest -q
```

Формулы (N/A, шкалы, округление, грубые ошибки, новый критерий без правки кода), проверка ответов модели,
повтор при невалидном ответе, переключение провайдера, время реплик и ссылка на запись.

## Демо (5 минут)

1. «Диалоги» → открыть чат → транскрипт.
2. «Оценить» → итог, секции, обоснование → клик по доказательству → подсветка реплики. Критерий с N/A. Звонок: ▶ перематывает запись.
3. «Оспорить» критерий → «Апелляции» → «Изменить оценку» + причина → итог до/после → карточка показывает исходную оценку, решение и новый итог.
4. «Чек-лист» → заменить критерий → «Сохранить как v2» → «Переоценить» → в карточке диалога история оценок v1/v2.
